# WindScore

面向电吹管演奏者的**简谱与五线谱动态谱工具**：写谱 → 对轨（配伴奏并对齐节奏）→ 入库 → 演奏 → 导出 PDF／PNG／SVG／视频。一套源码同时跑桌面（Tauri exe）和浏览器，曲库与伴奏保存在本机。听音成谱实验入口目前隐藏。

界面使用 Canvas：排版与绘制分离，简谱与五线谱共用曲谱数据和播放时间线；五线谱已支持符头与倚音点击定位，完整的五线谱直接输入和记号命中仍在开发计划中。

## 使用帮助

完整分类手册见 [WindScore 使用帮助](docs/user-guide.md)。首页点击「帮助」进入 `help.html`；记谱、源码、对轨、曲库与播放界面也提供帮助按钮，在窗口中查看同一份文档，支持分类、关键词搜索与深浅色。关闭帮助可继续当前操作。

手册覆盖重奏、歌词、变拍号、换行/分页、反复与跳转，以及 PDF、视频、PNG 和 SVG 输出；以下章节保留项目背景与开发说明，日常操作以分类手册和当前界面为准。实验入口目前隐藏。

## 音色素材与许可

合成音的钢琴来自 [Salamander Grand Piano v3](https://archive.org/details/SalamanderGrandPianoV3)（Yamaha C5 实录，作者 Alexander Holm，[CC-BY 3.0](https://creativecommons.org/licenses/by/3.0/)），由 `scripts/build-piano-samples.mjs` 按音区裁到 3~8s 完整自然衰减（含包络整形：抹平录音自带的拍音起伏与音腹后回鼓），拼接为 `public/piano-samples.mp3`（96kbps 单声道，约 1.9MB）+ `public/piano-samples.json`（偏移清单），运行时经 `AudioContext.decodeAudioData` 解码整段回放——绝大多数音符从头到尾都是真实录音，合成只兜底并续超长音尾部；琴体共鸣/混响（`src/v2/reverb.ts`）为本项目纯合成。按 CC-BY 3.0 要求在此署名。

## 动态谱演奏（play.html）

首屏是**动态谱首页**（左中右三栏）：

- **左**：最新动态、我的收藏（点 ☆ 收藏，常用的置顶）
- **中**：全部曲目，右侧首字母索引 A/B/C 可直接跳
- **右**：最近搜索（可单条删除 / 清空）
- 顶部搜索框：搜歌名或谱面标题，回车搜索

点任意一首进**播放界面**：

- 音源：**伴奏**（用对轨标定的真实分轨）/ **合成音**（按谱面奏，三角波）随时切换；没对过轨的歌「伴奏」自动置灰
- 反复处理：**原谱 / 展开反复**——展开后反复与 D.S. 按顺序铺开，指示条、滚动、导出都按线性谱走
- 播放指示：**光标**（当前音底色与竖线）/ **高亮条**（简谱从行首随音乐变宽；五线谱为按节拍连续前进的窄竖带）/ **光球**（带光晕与拖尾，五线谱按实际符头高低跳跃）；选择存本地，换歌重开都记得
- 顶部可切换**简谱／五线谱**，点击音符选择起播位置；五线谱按钮内的齿轮打开记谱配置
- **字号 / 字距**滑杆：播放时的观看偏好，只影响显示，谱面文件不变；改完存本地，换歌重开都记得
- **导出**：PDF、PNG、SVG 与视频（见下）

## 简谱编辑（editor.html）

### 记谱

| 类别 | 支持 |
|---|---|
| 音符 | 音级 1–7、休止 0、隐藏休止 8、X 无音高音符（打击 / 拍手，发声无固定音高）、高/低八度点、变音记号五种（♯ × ♭ ♭♭ ♮，GB/T 46845—2025） |
| 时值 | 减时线（1/2、1/4、1/8 拍）、增时线（2 拍、3 拍…）、单附点与双附点 |
| 节奏 | 拍内组自动连减时线、三连音 / 六连音（断弧 + 标号）、连音线、延音线 |
| 结构 | 隐藏小节线 `|*`（占位不画线，用于行中混排的空拍占位）、虚小节线 `|~`（画虚线、校验照常，GB §5.2.2）、散板「散」（自由拍子段落免拍数校验，GB §6.3.11.7）、小节反复号 `%`（𝄍，播放重复上一小节）、多小节休止 `0*8`（粗横线 + 上方小节数，删增格子自动重算）、高低八度演奏段 `8va[ … ]8` 与八度重复 `con8[ … ]8`（需 @format 3；选区按钮循环三态 8va → con 8 → 取消；段可跨行——上行虚线到行尾不折角，续行标括号 (8)；GB/T 46845—2025 §5.8.4 / §6.3.7.3 / §6.2.6） |
| 装饰 | 前倚音 / 后倚音（最多三颗，可带八度与变音）、段落文字标注（选中音符后在属性面板输入，谱面显示为 `(文字)`）、左右括号 `（ ）`（画在音符左右两侧，可跨行） |
| 提示 | 批量**灰显**（前奏 / 间奏标记）：选区一键 灰显 / 复原，音符与休止画成灰色，播放不受影响（DSL 后缀 `g`） |
| 演奏记号 | 吐音 T / K、换气 V、断音 ·、保持音、重音、延长音、花舌、打音、波音、滑音、弯音、颤音（tr + 波浪延展线）、回音、指法数字（0–5）、琶音（波状竖线）、震音（1–3 条斜线，播放按 2^n 细分重复） |
| 力度 | `pp p mp mf f ff` 与渐强 / 渐弱 |
| 转调 | 任意音符上标 `转1=G`，从该音起改用新调 |
| 版式 | 谱面字号、字间距、行间距增量（写在 `.jps` 里，打开即还原） |
| 校验 | 每小节拍数、拍内组不变量 I1–I5，工具栏实时显示 |
| 编辑 | 撤销/重做、复制粘贴、拖拉建选区、源码视图（实时解析，切回简谱自动应用） |

## 五线谱与移调

- 编辑页顶部为 **简谱／五线谱／源码**；动态谱生成页和播放页也可切换简谱／五线谱。无需打开实验功能区。
- 点击“五线谱”文字切换视图，点击按钮内右侧齿轮配置**实音谱／乐器移调谱、当前声部的记谱乐器及默认／高音／低音谱号**。多声部先切换声部，再分别配置；音色与记谱乐器相互独立。
- 默认高音优先，只有至少八成时长权重需要三根以上下加线、且低音谱号能大幅减少加线时，默认／`auto` 才采用低音。一般低音只在齿轮配置中建议，由用户应用；手动高／低音优先，不改变八度或声音。
- 低音谱号按实际字形墨迹定位在谱表中部；谱线两端以竖线收口，行尾有小节线时不再添加外伸留白。𝄋 在按钮和两种谱面中已缩小。
- 首批预设：C 调、B♭ 单簧管、B♭ 次中音萨克斯、E♭ 中音萨克斯。配置随 JPS 保存，不改变实际播放音高、伴奏或对轨数据，也不控制电吹管硬件移调。
- 已显示倚音、延音／圆滑线、主要技法与力度、渐强渐弱、跳转及跨行反复房子；重奏左侧连接符和各声部谱线共用系统边界。
- 密集排版按实际书写变音记号与前后倚音预留空间，负字距也保留这些记号的安全宽度；重奏同拍统一分配空间。行首谱号避开倚音和转调记号，连音组编号与括线为附近倚音、连线让位。
- 技法、力度及渐强渐弱会避开符杠、临时变音、倚音和连音组；仅在横向与纵向同时碰撞时分层。连线占用按实际弧线极值计算，减少控制点造成的额外留白，歌词仍排在下方内容之后。
- 嵌套连线按内层到外层排布，外层圆滑线按实际间距避开同方向的内层连线，端点仍连接符头附近；分叉／汇合连接会保留，跨行方向连续。任意交叉连线的全局避让仍待完善。
- 原谱显示反复双线与外侧双点、跳房子和跳转；反复超过两遍显示总遍数。修正连续反复边界同步至其他声部时漏掉新起点的问题。「展开反复」显示已展开小节，不保留反复记号。
- D.S. 跳回目标在按钮、简谱、五线谱及导出中统一使用标准 Segno **𝄋（U+1D10B）**，源码仍为 `$s`。
- 屏幕及 PDF／图片／视频使用同一五线谱绘制；导出直接跟随乐谱的记谱配置。视频按所选画幅另行排版，保留动效。
- 仍待完善：复杂记号精细避让和完整五线谱直接编辑；浏览器下载／EXE 保存、整曲播放与完整伴奏视频的专项验收仍未全部完成。详见 [开发计划](docs/roadmap.md)。

## 歌词延唱与连字

- 进入歌词标签，选后续空格点 **延唱**（Ctrl+E），选前一英文音节点 **连字**（Ctrl+H）；**取消连线**（Ctrl+Shift+E）仅清除本格标记。延唱格显示「延」，可退格删除，支持撤销。快捷键被浏览器占用时使用按钮。
- 空格仍是普通空位，不自动猜测延唱；休止打断连接，跨行自动续接。插入空位、退格删除及更换关联声部时，标记随歌词格移动。
- 简谱／五线谱、PDF／PNG／SVG／视频和横幅共用连接几何；整行只有延唱也保留空间。示例列表新增「歌词延唱与英文连字」。
- JPS 格式 3 使用独立行 `歌词线1: 2~ 3~ 5-` 保存主音位置与连接类型，原有歌词文字及 `_` 语义不变；新文件需本次更新后的程序读取。详见[分类手册](docs/user-guide.md)。

## 动态谱生成（align.html）

从首页进入独立页面，继续当前曲谱或点击「打开」选择 .jps。曲库管理中的「对轨」也会带着所选曲目进入本页。沿用已有伴奏和标定数据。

1. **载入音频**：一次可载多条分轨（人声 / 伴奏），可单独静音；`wav` 载入时**自动压成 mp3** 再入库
2. **核对网格**：载入后自动估 BPM 并铺出节奏线；整体偏了**拖任意一条节奏线**整组平移（Shift 细调，线距太密时拖拽是平移视图），速度估错了点「打拍定速」——跟着音乐按空格，波形上有拍点与预测网格线，停 2 秒自动结算
3. **绑定对齐点**：波形上点一条节奏线 → 谱面点一根小节线 = 绑定；谱面最左端还有虚拟的「开头」靶标对应第 0 拍。**边听边修**：播放中发现指示条跟不上伴奏，按 `N` 就地暂停加对齐点。**两个以上对齐点自动生成变速曲线**，前奏偏长、中段变速、结尾渐慢都靠多加对齐点解决
4. **单点微调**：某个字总差半拍时，谱面选中那颗音 → 波形点在正确位置 → 「手动输入与诊断」里的「把选中的音对到这里」；折叠区里还有手动 BPM / 快速锚定 / ÷2 ×2 兜底
5. **音轨分离**（顶栏按钮）：免费的 OD Trama 下载地址，先把整首歌拆成分轨再载入
6. **打包**：把谱面 + 伴奏 + 标定打成一个 `.wspack`，分享给别人可完整还原

点击波形会从该处试听；波形上方工具栏的“试听 _ 拍”控制自动停止时长，默认 8 拍，设置保存在本机。

## 曲库管理（library.html）

- 导入 `.wspack`（谱面 + 伴奏 + 标定一起进库，别人发的也能用）、收录 `.jps` 谱面
- 重命名、删除、打包分享（导出 `.wspack`）
- 曲库列表显示调号 / 拍号 / BPM / 小节数 / 音符数，坏谱标红但不拦着删或导出

## 导出

**PDF**（打印 / 投影）

- A4 纵向／横向，150 或 300 dpi；保留当前谱面的行内容和字形比例，按纸张等比缩放并分页，没有独立的隐藏字号配置
- 可选首页标题与小节号；多页自动分页，导出不画页脚页号
- 弹窗中提供逐页画面预览，可缩放检查；重奏按整组声部分页

**PNG／SVG**（图片）

- **连续长图不分页**：整谱从上到下一次画完，标题在最上；与 PDF 共用排版，支持浅色／深色和总谱／分谱
- PNG 适合直接发送；SVG 保留矢量路径，文字与谱号仍依赖打开设备的字体
- PDF、图片与视频均跟随当前谱式和实音／移调配置；需要换乐器或谱号时先在乐谱界面修改

**视频**（分享到手机 / 群）

- 九档比例：`9:16`、`16:9`、`16:10`、`10:16`、`4:3`、`3:4`、`3:2`、`2:3`、`1:1`
- 分辨率短边 720 / 1080 / 1440；帧率 25 / 30 / 60
- 声音：伴奏（真实分轨）／合成音；外观可选浅色／深色
- 画面按所选比例**重新排版**并随播放位置滚动，带播放指示与底部进度条
- 离线编码（WebCodecs + mediabunny），不用实时播放；实际耗时取决于设备、曲长、分辨率与帧率。MP4(H.264+AAC) 优先，不支持则 WebM(VP9+Opus)

## 存储与迁移

曲库数据只有一种格式——**一个文件夹**：

```
曲库文件夹/
├─ library.json   全部曲目（清单 + 谱面文本）
├─ align.json     每首歌的对轨标定
└─ audio/…        伴奏分轨（wav 一律压成 mp3 后进库）
```

| 运行环境 | 存哪 |
|---|---|
| 桌面版 exe | 应用数据目录（Windows 是 `%APPDATA%`） |
| 浏览器（Chrome / Edge） | 你选的一个真实文件夹（File System Access API，与 exe 版格式完全一致） |
| 兜底（其他浏览器 / 没选文件夹） | localStorage + IndexedDB |

**迁移 = 拷贝这个文件夹**。首次连接文件夹时，原有曲库会自动迁进去；断连期间写进本地的歌，重连后自动合并回来。浏览器重启后授权会失效，页面点一下即静默续权；曲库页有「重新连接」按钮兜底。

## 快速开始

```bash
npm install
npm run dev         # 浏览器预览 http://localhost:5173
npm test            # 内核回归测试（1000+ 条断言，纯 Node 跑）
npm run build       # 类型检查 + 生产构建
npm run tauri:dev   # 桌面版开发（需 Rust 工具链）
npx tauri build     # 打包 exe / 安装包（产物在 src-tauri/target/release）
npm run build:skill # 重新打包 skill 里的独立校验器（改了 dsl/validate/layout 后要跑）
```

### 版本号

当前工作区版本 **0.4.31**，显示在落地页页脚及安卓“我的”页。每次交付代码修改必须递增版本，通过以下脚本统一处理：

```bash
npm run version              # 递增修订号
node scripts/bump-version.mjs minor   # 递增次版本号
node scripts/bump-version.mjs major   # 递增主版本号
```

脚本同步 `package.json`、`package-lock.json`、Tauri 配置、Cargo 清单/锁文件和 Android `versionName`，同时递增 Android `versionCode`。落地页由 Vite 注入版本，安卓“我的”读取原生包版本。版本递增后重新构建所需端的安装包；同一轮修改重复编译沿用同一版本。

PC/Tauri 有实际代码变化（包括影响 PC 的共享逻辑）时编译一版 exe，纯安卓修改不每次重编译 PC。交付的 exe 同样复制到 `artifacts/releases/`，文件名保留版本号。

浏览器版没有原生文件对话框：保存 = 下载 `.jps`，打开 = 用文件选择框。桌面版走系统对话框，能拿到真实路径。

## 构建产物与命名规则

**交付只认一个目录：项目根 `artifacts/releases/`**。构建工具自己的输出目录是中间产物，不用于分发，也不入库（`dist`、`dist-android`、`android/app/build` 均在 `.gitignore` 中）。

| 端 | 构建命令 | 中间产物（不交付） | 交付文件（复制到 `artifacts/releases/`） |
| --- | --- | --- | --- |
| 网页 / 浏览器 | `npm run build` | `dist/` | —（部署 `dist/` 本身） |
| 安卓资源 | `npm run build:android` | `dist-android/`（相对路径构建 + WebView 资源检查） | —（打进 APK） |
| 安卓调试包 | `gradle -p android assembleDebug` | `android/app/build/outputs/apk/debug/app-debug.apk` | `WindScore-<版本>-android-build<构建号>.apk` |
| 安卓发布包 | `gradle -p android assembleRelease` | `android/app/build/outputs/apk/release/app-release.apk` | `WindScore-<版本>-android-build<构建号>-release.apk` |
| 桌面 exe / 安装包 | `npx tauri build` | `src-tauri/target/release/bundle/`（`msi/WindScore_<版本>_x64_en-US.msi`、`nsis/WindScore_<版本>_x64-setup.exe` 等） | `WindScore-<版本>-windows.exe`（免安装）、`WindScore-<版本>-windows-setup.exe`（安装版） |

命名与版本规则：

- 版本号以 `package.json` 为唯一来源，由 `npm run version` 递增，并同步 `package-lock.json`、`src-tauri/tauri.conf.json`、`Cargo.toml`/`Cargo.lock` 与安卓 `versionName`，同时把安卓 `versionCode` 加一。**同一轮修改的重复构建沿用同一版本**，不因改动单个文件反复递增。
- 文件名一律 `WindScore-<版本>-<平台>[-类型].apk|.exe`，安卓文件名带构建号；**不要交付同名 `app-debug.apk`**，否则分不清手机上装的是哪一版。
- 手机上判断装的是哪一版，看「我的」页底部（`安卓版 <版本> · 构建 <号>`）；启动地址带 `?build=<构建号>`，只恢复同一构建的历史，避免升级后回到旧界面。
- Gradle 的 `preBuild` 会自动先跑 `npm run build:android` 再同步 `dist-android` 进 assets，所以**改了 web 代码直接跑 assemble 即可**，不用手工拷资源。
- 安卓环境要求：JDK 17、Android SDK（platforms;android-34、build-tools;34.0.0）、Gradle 8.6；`android/windscore.keystore` 是自签签名文件，只留本机、不入库。
- 有实际代码变化（含影响 PC 的共享逻辑）时编译一版桌面 exe；纯安卓修改不要求每次重编译 PC。

## 文件格式 `.jps`

纯文本，UTF-8。结构 = 头部元信息 + 空行 + 谱面主体（token 用空格分隔）：

```
@title 茉莉花
@key 1=G
@beat 2/4
@bpm 48
@patch 73
@sub 铃木教程二重奏分谱
@note 长笛(*和声常开)
@note 程序员老许制谱

<3/2 3/4 5/4> <(6/4 1^/4) 1^/4 6/4> | <5/4 (5/4 6/2)> 5t | ...  ||

```

- 头部：`@title @key @beat @bpm @patch @patchName`（后两项可选），版式参数 `@size 字号` `@space 字间距`（未改过不写）
- 谱头说明：`@sub` 是标题下的居中说明行；`@note` 是谱头右侧的说明行（每条一行，最多 4 行）。
  谱头按「左中右」三区排版：左 = 调号 / 拍号（叠写）/ 速度，中 = 标题 + 说明行，右 = 说明行
- 主体：`5`=1 拍、`5/2`=半拍、`5-`=2 拍、`5.`=1.5 拍、`5^`=高八度、`X`=无音高音符（打击/拍手，发声无固定音高，时值/附点写法同音符）、`<…>`=拍内组、`<3: …>`=三连音、`5~5`=延音线、`(5 6 5)`=连音线、`{2}3`=前倚音、`5V`=换气、`5t`=吐音、`5g`=灰显（前奏/间奏提示）、`转1=G`=转调
- 版式参数：`@size` 字号、`@space` 字间距（可负）、`@lineGap` 行间距增量（正数拉开行距）
- 左右括号：全角 `（` / `）`（半角 `(` `)` 是连音线，别混）。两个记号各自独立、不占时值：
  一段的头一个音前写 `（`，末一个音后写 `）`，中间隔几行都行——谱面在音符左右两侧画出括号，如 `（ 6 2 2 ）`
- **独立换气记号 `'` 已从规范删除**，遇到会报错；换气写作音符后缀 `V`

完整语法：`skills/windscore-jps/reference.md`（给人和大模型读的规范）。设计决策与不变量：`windscore-v2-spec.md`。

## 让大模型帮你写谱

`skills/windscore-jps/` 是一份可直接挂到 Agent 上的技能包：把简谱图片或文字谱交给它，它按规范生成 `.jps` 并用内置校验器自检到 `PASS`。

```bash
node skills/windscore-jps/validate.mjs 曲名.jps   # PASS / FAIL + 退出码
```

校验器内嵌了本程序自己的解析器与不变量（不是另写一套），所以「校验通过 ≈ 程序能无损打开」。改了 `dsl.ts` / `validate.ts` / `layout.ts` 之后记得 `npm run build:skill` 重新打包。

## 开发约定

安卓独立界面的浏览器预览：启动 `npm run dev` 后打开 [示例预览](http://localhost:5173/android.html?preview=1)。预览自带曲目，收藏、删除与导入只在本次内存中生效；[普通入口](http://localhost:5173/android.html) 使用当前浏览器的本地曲库。使用浏览器响应式模式切换手机和平板尺寸、横竖屏，可直接检查页面效果与播放操作。

安卓曲库中点击曲目右侧“…”可重命名。名称不能为空或与其他曲目重名；保存时保留收藏、伴奏和标定关联。PC/Tauri 曲库重命名共用该关联迁移逻辑。浏览器示例预览中的改名仅在本次预览有效。

安卓安装包统一交付至项目 `artifacts/releases/`，不再引用其他目录中的 `app-debug.apk`。`gradle -p android assembleDebug` 或 `exportDebugApk` 自动输出 `WindScore-<版本>-android-build<构建号>.apk`；Release 对应 `assembleRelease` 或 `exportReleaseApk`，文件名追加 `-release`。先用 `npm run version` 递增版本，保留旧版文件供追溯；“我的”底部显示实际版本与构建号。启动时只恢复同一构建的安卓独立入口历史；升级不更换曲库存储位置。

`npm run build:android` 构建安卓资源并检查 WebView 路径；`npm run test:android` 检查字号按屏宽重排、播放和曲库检索。详细产品约定见 [安卓界面设计](docs/superpowers/specs/2026-10-20-android-app-design.md)。

### 电脑向安卓上传曲库

安卓 App 的“我的 → 从电脑上传曲谱”中点击“启动曲库服务”，复制显示的完整地址到电脑浏览器。电脑和手机须连接同一无线局域网；不要求局域网能访问互联网，仅移动数据不能启动。地址包含本次服务的连接凭证，停用后失效。

电脑可选择或拖入 `.wspack`，每批 1～9 个、单文件不超过 100 MiB、每批合计不超过 500 MiB。手机依次校验包结构、完整性、谱面和标定，保存伴奏与曲库后，两端显示实际导入结果。同名曲目自动编号；单份损坏不影响同批其他文件。电脑首次建立心跳后，手机显示“电脑已连接，等待上传曲谱”；15 秒未收到心跳显示断开。

服务启动后可切换到聊天软件发送地址，通知栏服务保留监听及同一个连接凭证。传输期间请保持双端亮屏，手机回到 WindScore 后完成校验入库；电脑会显示等待手机返回的提示。服务在手机前台运行时自动保持亮屏；Wi-Fi 断开/地址变化、手动停用、退出 App 时停止并清理暂存文件。已经导入的曲目保留。

切换到 App 内的“曲库”或“社区”会自动停用上传服务，回到“我的”后需重新启动；这与切到聊天软件发送地址不同。复制地址使用安卓原生剪贴板，成功后提示在同一局域网的电脑浏览器打开，普通操作提示 3 秒自动关闭。

浏览器中的安卓预览提供启停面板演示；[电脑上传页预览](http://localhost:5173/windscore-upload.html?demo=1) 可查看界面并选择文件，明确标注不会上传或写入手机。真实 Wi-Fi 地址和原生 WebView 导入需在 APK 中使用。实现与验收范围见 [局域网上传设计](docs/superpowers/specs/2026-10-20-lan-upload-design.md) 和 [实施计划](docs/superpowers/plans/2026-10-20-lan-upload.md)。

- 内核（types / dsl / edit / layout / validate / timeline / tempo）不依赖 DOM，可在 Node 里直接测
- 任何编辑操作都是 `edit.ts` 里的纯函数：`(score, …) => Score`，改一处只走一条写入路径
- 排版 / 绘制 / 命中三处必须用同一套度量（`layout.deriveGlyph`），各写一份就会出现「看着点在缝里、实际被判成点在音上」
- 曲库的读写只走 `libraryStore` / `alignStore` 一个出口，后端（文件夹 / 本地）由 `storeBackend` 决定
- 界面文案说人话，内部术语（BeatGroup、不变量编号）不出现在面板上
- 每次代码改动都要按根目录 `AGENTS.md` 做跨端影响检查：逐一判断浏览器、Android 和 Tauri 桌面是否需要同步；共享代码至少检查浏览器与 Android 的受影响入口，平台专属改动要记录其他端不适用的原因
- 交付时列出检查过的端、同步改动、无需同步的理由，以及未验证项；布局可用浏览器响应式预览检查，不要求每轮都用 Android 真机
