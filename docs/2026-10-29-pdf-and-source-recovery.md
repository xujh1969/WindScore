# 0.4.25：PDF 兼容性与错误谱面修复

## 已确认原因

旧的 A4 几何以浮点像素计算。150dpi 纵向为 1240.166666… × 1753.9375；Canvas 位图宽高则是整数。旧流程把几何小数直接写入 PDF 图片字典 `/Width` 和 `/Height`，没有使用位图实际尺寸。

[Adobe PDF 规范](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf)要求图片的宽高字段为整数（纸张 `/MediaBox` 的点尺寸可为小数，不能混淆）。这会形成阅读器兼容性问题，GPU 回读保护无法修复文件字典的错误。

本轮制作两个仅改变图片宽高字段的单页 A/B 文件：图片 JPEG 字节、纸张、页内容完全相同。A 写 1240×1754，B 写 1240.16667×1753.9375。独立 PDFium 渲染 A 正常、B 空白；用户也实测 B 在 Edge 空白、Acrobat 正常，确认该兼容性故障可以重现。尚未拿到最初其他用户的故障 PDF，因此不声称它解释所有历史故障。

对照文件保存在 `artifacts/pdf-compatibility/`。B 是故意不符合规范的测试文件，不应作为正式输出分享。已有乐谱建议用新版重新导出 PDF；没有原谱时，可在能正常显示的阅读器中打印为新的 PDF，不能假定简单“另存为”一定会修正图片字段。

## PDF 修复与诊断

- A4 绘制像素统一取整数，图片声明使用实际 `canvas.width/height`。PDF 组装器拒绝非整数/非正数的图片尺寸或空数据，纸张点尺寸保持准确。
- 每页新建请求 `willReadFrequently` 的内存后备画布，从绘制到编码减少 GPU→CPU 拷贝与复用状态残留；浏览器决定实际后备实现，不宣称它能替代显卡驱动诊断。
- 逐行检查正文，避免标题或页脚让空白正文通过；检查画布上下文丢失，校验器不可用时不再静默放行。
- JPEG 编码后检查实际 MIME、文件标记，再解码核对尺寸及正文墨迹；字体准备、编码与解码设置超时。资源在每页结束后释放。
- Windows 在显示保存成功前，重新打开磁盘 PDF，核对长度、文件头与结束标记。这个检查不等于完整阅读器验证，完整图片/PDF 验证在写盘前完成。
- 发布版记录阶段日志 `pdf-export-latest.jsonl`，与已有视频日志分开。包含应用版本、WebView UA、分辨率、页数、阶段、检查结果、编码字节数和异常，不主动写入谱面正文。每次导出重置该日志。

### 出现新故障时收集什么

1. 保留原始故障 PDF，不先用别的工具修复覆盖；记录哪个阅读器/版本空白、哪个能显示，以及整份空白还是只有部分页空白。
2. 用 0.4.25 或更新版重试一次，随即复制错误提示中的诊断日志；Windows 默认位于 `%APPDATA%\com.ayou.windscore\logs\pdf-export-latest.jsonl`，以提示的实际路径为准。再次导出会覆盖它。
3. `page-render` 后失败：优先查绘制/正文检查；`page-encoded` 后失败：查图片编码与解码；`pdf-built` 后失败：查文件保存；出现 `save-complete` 但特定阅读器不显示：优先查 PDF/阅读器兼容性并保留样本。
4. 把应用版本、故障 PDF、阅读器版本和日志一起提供。不能仅凭系统同为 Win11 推断是同一种故障，也不需要一开始就要求用户修改显卡设置。

## 错误谱面仍可继续编辑

确认原来有两条风险：现代格式解析报错后拒绝打开；部分旧格式即使报错仍返回部分 Score，打开再保存可能把未识别记号丢掉。

- IO 保留原始文本、路径与文件句柄；有任何解析错误时不把部分 Score 当完整谱面。
- 桌面/网页编辑器以源码修复模式打开，显示实际错误；只在用户修正并通过解析后，才应用到图形谱面。
- 源码视图的保存写入当前原文，不序列化占位谱面；支持浏览器句柄写回、Tauri 文件保存和曲库条目更新。保存/自动恢复都保留未知记号及换行。
- 自动恢复保存当前源码草稿；初始化同步不得把它覆盖成空白占位谱面。“丢弃改动”回到已保存的原文。
- 损坏曲库条目提供“修复”；无法播放时可转入修复，不再建议用户删除文件。原始含错误的内容不会因播放失败而自动改写。
- Android 依旧是播放端，不增加编辑功能；错误谱不能直接播放，应在桌面/网页修好后再导入。
