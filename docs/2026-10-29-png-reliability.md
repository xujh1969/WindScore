# PNG 长图导出稳健性检查（0.4.26）

## 发现与修复

PNG 原实现已对宽高 `Math.ceil`，不会把 PDF Image 字典的小数尺寸问题带入 PNG；2048px 横条按整数位置首尾拼接，也没有发现接缝坐标累计误差。

仍存在可复现的漏检：整条只检查一次墨迹，有几行残留就会放行；备用 CPU 绘制同样空白时被当作合法留白。编码器输出没有解码复查。故障注入将编码结果 y=700–1300 擦成白色，旧实现仍返回保存成功；新实现会在第 4 行报错并阻止保存。

本次在 `image.ts` 内完成最小范围加固：

- 拼接后按排版中的可见音符/休止行逐行检查，隐藏休止行和真实留白不要求有墨。
- PNG 格式与文件头检查，解码后核对实际尺寸并再次逐行检查；正文丢失不能被标题掩盖。
- 校验画布不可用时明确报错，不按成功处理。
- 字体等待、编码及解码增加 20 秒超时。
- 横条使用后立即释放，长图和解码资源在成功、失败时均释放。校验只复用一张行高的小画布，不再创建第二张完整长图画布。
- 保留原 GPU 横条/CPU 回退方案，避免改动既有字形绘制行为；超限仍建议降低 dpi 或改用分页 PDF。

## 回归方法

`npm run dev` 后打开 `/scripts/png-reliability.html`。使用独立端口可避免影响日常曲库会话。

页面覆盖普通/深色简谱、五线谱、绘制中段丢失、编码后中段丢失。样例 64 小节，简谱 32 行 1240×5341，五线谱 64 行 1240×11747，均跨多个 2048px 接缝。

## 跨端范围与限制

浏览器和 Tauri 的编辑/对轨页共用该导出函数，统一更新。Android 主播放界面没有导出功能，不增加导出 UI；校验 Android 多页构建与资源路径以确认共享依赖仍可打包。PDF/SVG/视频的绘制器未修改。

这是空白行与编码完整性的防护，不是逐音符语义识别：同一行中少量字形缺失、五线谱保留谱线而个别音符缺失，不能只靠墨迹检查完全判断。未在原用户故障显卡上复现，也不把浏览器检查视为所有 Win11 驱动环境的验收。

## 本轮验证结果

- 浏览器：简谱、深色简谱、五线谱 PNG 均下载成功；Pillow 独立解码、尺寸和每个 2048px 横条的像素检查通过，接缝样张已查看。
- 故障注入：绘制中段缺失、编码后中段缺失均在第 4 行被拦截；编码故障在修改前曾返回保存成功。
- `npm run test:pdf-reliability` 通过，网页/Tauri 生产构建通过，`build:android` 及相对资源路径检查通过。
- Windows 0.4.26 exe/MSI 已编译并复制到 `artifacts/releases/`；本轮没有在打包后的 WebView2 中实际操作导出，也没有原故障显卡验收。
- Android 只同步项目版本（build153）并验证资源构建；本次没有安卓功能改动，未重发 APK。

样张、像素检查记录和截图保留在 `artifacts/png-reliability/`。
