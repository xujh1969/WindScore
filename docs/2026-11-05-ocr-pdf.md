# 0.4.61 PDF 输入与 OCR 空结果

网页在旧 Chromium 上用桌面《北国之春.pdf》复现 `this._intentStates.getOrInsertComputed is not a function`。此前使用 pdfjs-dist 6 的现代构建并手工补 TypedArray API，遗漏 Map 等能力。现改用同版本官方 legacy 主线程和 worker，删除自制 TypedArray 补丁及其实现细节测试。参考：https://mozilla.github.io/pdf.js/getting_started/ 。

PDF 解码不再先通过 operator list 等待最大内嵌图对象，而是调用整页 render，扫描图、矢量、旋转和页内文字采用同一路径。页面像素生成预览后保留；点击识别直接按页序在 CPU 拼接同一组二值像素，不再重新打开 PDF 或通过长画布回读。取完页面后释放文档 loadingTask。空白输入及零音符结果保留在启动页并显示原因，不进入空编辑器。选择新文件时清掉旧 pending，避免新文件失败后仍识别旧文件。

影响范围：浏览器及 Tauri 共用 ocr.html / OcrPage / PDF 解码器。其他 index、editor、align、library、play、help、musicxml 入口没有独立 PDF OCR 实现。Android 的产品入口不提供 OCR；不修改安卓业务或原生逻辑，版本与构建号同步为 0.4.61 / 188。Android 构建与 HTML 资源路径检查通过，不代表真机验收。

回归脚本：`scripts/ocr-pdf-browser-test.mjs`。对 Vite dev 或 `WS_TEST_URL` 指定的生产预览测试；`PLAYWRIGHT_MODULE` 可指定外部 Playwright ESM 地址，`CHROMIUM_PATH` 指定旧版 Chromium。`WS_CDP_URL` 可连接启用调试端口的独立 EXE 实例。测试实际 PDF 预览墨迹、真实模型识别、左右两栏画布内容和空白 PDF 的失败提示；截图保存在 `artifacts/ocr-pdf-fix/`。

浏览器使用 Chromium 136，开发和生产预览均通过《北国之春.pdf》完整链路及空白 PDF 拦截。MusicXML 回归通过。识别准确率仍需人工校对，此次修复不保证每个音符、时值或歌词均正确。

Windows 原生 EXE 的 WebView2 内也已通过《北国之春.pdf》载入、非空预览、真实 OCR、左右栏画布内容检查，截图为 `artifacts/ocr-pdf-fix/exe-compare.png`。另通过两页矢量 PDF、90° 旋转页及翻页测试。

## 同轮补充：小节线操作

选中小节线时原面板将普通输入板整个替换，导致删除入口消失；取消特殊样式依赖再次点击原按钮，缺乏直接入口。现补充「普通小节线」「删除小节线」。类型切换复用输入板的就地转换路径，清理反复、遍数与虚线的冲突状态，保留拍号、速度、音色、断行及房子等独立属性。虚线切换同样清掉反复属性，避免视觉和实际演奏状态不一致。删除按钮和 Backspace 删除非音符事件后统一进入插入态，避免把前一个音符变成替换目标。

`scripts/barline-browser-test.mjs` 在真实编辑器中复现缺少删除按钮（修改前失败），验证终止→普通、终止→反复→双细→普通，以及删除、撤销、重做均保留邻接音符。V2 内核回归通过，包含小字谱；MusicXML、谱面格式和存储实现未变。小字谱复用 PadBody 类型签名，保留原有精简编辑规则。Android 为播放端，不展示此编辑面板。

最终生产网页（1280 / 1024 像素窗口）和发布 EXE 的 WebView2 均通过上述小节线交互测试；另验证删除后新音插入、不覆盖前音，以及输入板将反复线转换为虚线。最终普通构建、Android 构建及资源路径检查均通过；未做 Android 真机操作验收。

按用户追加的交互要求，小节线类型与删除改为同一排图标，位于排版设置之后：普通、反复开始、反复结束、双向反复、双细、终止、虚线、删除。面板顶端不再放文字按钮；反复线也使用与输入板一致的图形，删除与普通输入板共用同一个 SVG。选中任何类型后均保留整组转换入口。
