## 总体判读（四行）

1. **产品与受众**：给电吹管用户把纸面简谱做成能跟着伴奏走的动态谱；入口分为演奏 / 编辑 / 生成（对轨）/ 曲库 / 识别，主动作是写谱并对上伴奏。
2. **做得好、应保留**：全站右上角 × 已统一（`ExpClose`）；导出弹窗有进度、状态字与取消；`CustomGroupDialog` 实时给出「还差 X / 减短一些音」这类可执行下一步；`TrackDialog`、`PartsPanel`、`BankManagerDialog` 的删除都有确认；`AndroidLanUpload` 对设备隔离给了明确出路。
3. **像默认生成的**：关键规则塞进 `title`、按钮只剩符号、10–11px 功能字、禁用只靠 opacity、toast 复述界面已看得见的变化、同一对象三套叫法、五份 CSS 各写一套按钮 / 选中态 / 阴影配方。
4. **真正坏了**：用户主动取消被报成「导出失败」；提示指向界面上不存在的页面与按钮；帮助文档与界面互相矛盾；安卓提示「用打包备份」而打包入口被隐藏；若干破坏性操作既无确认也不可撤销。

## 一、Floor · 不可豁免（1–9）

**1. [全站输入框] 焦点指示被移除** · `polish`
`src/v2/ui/editor.css:728`、`:2479`、`:3353-3356`；`src/ocr/ui/ocr.css:147,158`；`src/v2/ui/android.css:46-47`
`outline: none` 后替代只是 1px 边框变色，个别控件聚焦时画面零变化；全库几乎没有 `:focus-visible`，键盘用户不知道光标在哪。focus 环普遍用 `border-color` 而非 outline 实现。
**建议**：统一一条 `:focus-visible` 规则（2px outline、对比 ≥3:1、瞬时无淡入），删掉各控件的 `outline:none`；focus 不再改边框颜色。

**2. [Android / toast] 深色主题下文字与底色对比失败** · `polish`（未做渲染复核）
`src/v2/ui/android.css:17,166`；`src/v2/ui/editor.css:62,2816-2826`、`:63,2861-2863`；图标字符见 `src/v2/ui/toast.tsx:109`
白字压浅粉删除按钮约 1.9:1；白色 `✓` / `!` 压亮绿、亮黄同样不足。
**建议**：为危险按钮与状态图标配成对的 ink token（深底配深字或改深色底），按正文 4.5:1、图标 3:1 校验；深浅主题各测一次。

**3. [全站按钮] `:active` 按下反馈几乎全缺** · `polish`
`src/v2/ui/editor.css:187-205`、`:3317`（全文件唯一 `:active` 只改 cursor）；`src/ocr/ui/ocr.css:74-91`；`src/v2/ui/help.css:17-19`；对照 `src/home.css:176` 只有首页有
触屏与鼠标都没有「按到了」的反馈。
**建议**：给共享 `.v2-btn` / `.ocr-btn` 补 `:active`（仅 `transform` 或 `opacity`），一处定义全端继承。

**4. [弹窗 / 输入板] 禁用态只靠 opacity，部分状态与可点态同形** · `polish`
`src/v2/ui/editor.css:202-205`、`:982-988`、`:1028-1034`（禁用与未选中同为 `opacity:.16`）、`:1042-1049`（`is-locked` 无禁用语义）
**建议**：禁用三通道 = 原生 `disabled` + `cursor: not-allowed` + 除透明度外的底色/文字变化；`is-locked` 补 `aria-disabled` 与说明。

**5. [对轨 / OCR / toast] 常驻动画无 `prefers-reduced-motion: reduce` 兜底，且动画 width** · `polish`
`src/v2/ui/editor.css:1074,1475,2331,2854,3626`（只有 `no-preference`）；`src/ocr/ui/ocr.css:257,698,758,804-810`；对照 `src/v2/ui/android.css:245` 已做对
**建议**：补全局 reduce 规则关掉无限动画与宽度过渡；进度条改 `transform`/`opacity` 表达进度。

**6. [波形 / 曲库 / 工具条] 交互图形缺名称、emoji 与裸符号当图标** · `polish`
`src/v2/ui/AudioWaveform.tsx:674`（canvas 承担点击定位却无 label，对照合规的 `ScoreCanvas.tsx:842`）；`src/v2/ui/LibraryScreen.tsx:252,257,477-480`（`⋯` 无 `aria-label`）；`src/v2/ui/EditorApp.tsx:3931,3995`；`src/v2/ui/NoteFields.tsx:324,541`
**建议**：交互 canvas 补 `role`/`aria-label` 或可访问替代；emoji 换 SVG；所有纯图标按钮补可读名称。

**7. [8 个入口] 首屏依赖 JS、无 `noscript`、样式随 JS 加载** · `polish`
`editor.html:23-24` 及 `play/library/help/align/ocr/musicxml/android.html` 同款；`src/main.tsx:49-51`（OCR 懒加载 `fallback={null}`）
脚本失败即整屏空白，用户无从反馈。
**建议**：各入口加 `<noscript>` 与最小首屏骨架/加载态；OCR 懒加载给可见 fallback。

**8. [曲库行内改名] 控件高度在状态间跳动** · `polish`
`src/v2/ui/editor.css:2425-2432`（padding 6px）对 `:2467-2477`（padding 5px），32→30px
**建议**：统一两者高度与 padding，focus 环改 outline。

**9. [Android 播放页] `overflow-x: hidden` 裁掉谱面横向内容** · `polish`
`src/v2/ui/android.css:185` 覆盖 `src/v2/ui/editor.css:335` 的 `overflow: auto`
触控无法滚到被裁的内容。
**建议**：恢复可滚动（或改用 `clip` 并给替代滚动容器），不要用 `hidden` 吃掉内容。

**14. [配色令牌] 字面量绕过变量、两套体系互不相通** · `restyle`
`src/home.css:19-20,186-205`（整页几乎无变量）；`src/v2/ui/editor.css:635-652,2536-2549`（节拍器状态字只补了深色）；`src/v2/ui/android.css:3-20`（另立 `--an-*` 绿色体系）

**建议**：把首页字面量收进令牌；深浅各一套由同一组语义变量派生；安卓 `--an-*` 映射到同一语义令牌而非另立色板。

**15. [触控] 桌面侧命中区约 22px、相邻热区零间距** · `restyle`（未做渲染复核）
`src/v2/ui/editor.css:187-196,802-807,951-961,997-1003`（`.v2-cg-dot` 与 `.v2-cg-beam` 的 `gap:0`）；`src/home.css:299-311`（主题开关 22×22，PC 与安卓共用）；对照 `src/v2/ui/android.css:39` 的 44×44
**建议**：桌面命中区 ≥32–40px、触控 ≥44px；点/线热区之间加间距，减少误触。

**16. [顶栏 / 窄屏] 按钮无 `nowrap`、顶栏无 `flex-wrap`** · `polish`（未做渲染复核）
`src/v2/ui/editor.css:187-196,74-79,180-184`，仅 `:2020` 等零散局部补丁

**17. [首页 / 安卓] 开发与测试信息直接暴露给普通用户** · `polish`
`index.html:100,108,122,124,130`（「测试功能」「约 25MB 识别模型」、作者微信、版本号；注释里模型又写 26MB）；`src/v2/ui/MusicXmlImport.tsx:125`；`src/ocr/ui/OcrPage.tsx:458`；`src/v2/ui/AndroidApp.tsx:186,189`（「浏览器预览」、构建号）

## 六、设计系统锁定（`restyle` 前置）

第 12–15 条不要逐页补：先写一份 `design.md`（或等价的令牌清单），一次锁定以下内容，再让各端引用：

- 颜色：一组语义令牌（纸 / 面 / 墨 / 弱化字 / 强调 / 危险 / 成功），深浅主题各一套派生值，含成对的 ink token；
- 字号与行高：正文、标签、功能字下限，触控档位；
- 间距与圆角：`--space-*` 与每层级一个半径；
- 控件配方：按钮 / 选中态 / 输入 / 弹窗阴影各一套，含 `:hover`、`:active`、`:focus-visible`、`:disabled` 四态；
- 动效：只用 `transform` / `opacity`，全局 `prefers-reduced-motion: reduce` 兜底。

## 七、改动纪律与验收

- **保留 wiring**：所有链接、表单字段、handler、路由、`id`、`name`、`key`、`data-testid` 不得因改版丢失；编辑发生在拥有该标记的组件内。
- **不要改测试来让改版通过**；文案类改动建议反过来加源码断言防止再次漂移（参照 `scripts/v2-test.ts`）。
- **每批完成后**：`npx tsc --noEmit` → `v2-test` 主回归 → `npm run build`；若动了 `dsl.ts` / `layout.ts` / `validate.ts`，补 `npm run build:skill`。
- **跨端复核**：网页、Android WebView、Tauri 桌面共用同一份 TS 源码与 CSS 变量，改共享实现即可三端生效；但触控命中、双击替代、折叠降级需分别在 Android 布局里复核。
- **补渲染层验证**：本报告未截图，落地时应在可用浏览器/真机上复核第 2、12、15、16、44 条（计算对比度、折行、遮挡、真实命中区）。
- **分批提交**：建议按「实施顺序」表逐批小步提交，避免一次混入跨 50 条的改动导致无法定位回归。
