# 《青花瓷》人声转谱诊断

日期：2026-10-08。

## 输入与方法

- 原谱：`src/scores/qinghuaci.jps`，解析无错误。52 个小节，533 个记谱主音，10 个前倚音；包含前奏、间奏和尾奏，不能直接用这些总数评价纯人声转录。
- 用户提供的人声：`music/青花瓷/vocals.wav`，239.334 秒、44100 Hz、双声道浮点 WAV。
- 按现有服务输入方式转换为 22050 Hz 单声道 PCM16，使用现有 GAME medium、普通话模式重新识别全曲，得到 447 个原始音符。诊断输出留在 Git 忽略的 `.tmp-qinghuaci/`，未改动用户原谱或音频。
- 另用 librosa pYIN 分析 20–56 秒，检查每个 GAME 音符中间 60% 时段内、有声概率至少 0.5 的基频中位数。这是交叉检查，不作为人工标注真值。

## 确认的问题

1. **八度基准**：原谱播放音高比这份人声高约 12 半音。比较时将原谱降低八度；这不代表每个低音点都是模型错误。
2. **真实错音**：22.940–23.180 秒，GAME 输出 MIDI 38.944，原谱对应主音是 MIDI 57（对齐并降低八度后）。独立基频检测在这个音段没有足够的高置信有声帧，不能武断补成正确音符。
3. **半音量化**：23.460 秒的 GAME 54.820、25.090 秒的 54.605 都四舍五入为 55，而原谱对应 54。pYIN 也分别得到约 54.792、54.642；简单更换音高算法并未解决这些例子。
4. **分段转调**：原谱起始 `1=A`，第 41 小节内转为 `1=#A`。转调音原谱时间为 181.389 秒，拟合到音频约 181.718 秒。当前 Lab 只使用整曲单一调号，会把末段的正常升调写成大量临时变化音。
5. **节奏倍频**：原谱 54 BPM；同目录已有 `align.json` 使用 108 BPM。两种拍单位不能直接用于同一份谱，时值和小节对应会不同。该 JSON 不作为此次诊断的时间对齐真值。
6. **倚音覆盖不足**：原谱有 `{2}3`、`{3}5`、`{3}2` 等倚音，现有短倚音规则只覆盖 1–2 半音级进，无法覆盖三度装饰音。还可能混淆滑音、音节边界和独立音符。

## 对照数字的含义

对 GAME 音符中点拟合原谱时间（偏移 0.510 秒，时间比例 0.999，等效约 54.054 BPM），统一处理八度差后：

| 音高解码 | 中点与原谱对应音高一致 |
| --- | --- |
| 当前逐音四舍五入 | 409 / 447 |
| 整曲固定 A 调自然音级优先，距离阈值 0.85 半音 | 405 / 447 |
| 使用原谱分段调号进行同样的自然音级优先 | 418 / 447 |

**这些数字不是标准音符识别准确率。** 时间参数使用原谱拟合；比较不衡量漏音、额外起音、完整时值、前奏乐器或倚音完整度。最后一行还使用了原谱已知的转调位置，不能当作自动识别的结果。

首段独立 pYIN 对照中，在 89 个具有足够高置信基频帧的音段上，原 GAME 四舍五入有 81 个中点音高与原谱一致，pYIN 中位数有 79 个一致（初步使用固定 0.38 秒时间偏移）。没有证据支持直接用 pYIN 替换 GAME 就能提高本曲效果。

## 后续实现方向

保留 GAME 的音符边界，增加分段调号与音高解码：先识别/确认转调，再对模糊的边缘音高使用弱调式约束；高置信变化音保留。低置信和异常大跳进应显示为待核对，避免默默输出极低音。装饰音需要结合连续音高轨迹和主音稳定段识别。

原谱仅用来评价，不能在识别算法里硬编码《青花瓷》的旋律或转调时间。此次完成了诊断，尚未将分段调性解码或基频融合写入产品，也未证明模型错音已修复。
