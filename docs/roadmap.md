### A04 · 复核历史节拍检测失败记录【已复跑，已归因，修复待真实音频验证】（2026-10-15）

- 已复跑：仍是 `BEAT FAIL(3)`，与历史记录一致，非本轮（五线谱重构）引入——三个失败全部是
  **倍频歧义**：① 120 BPM 干净点击估成 60.01；② 残差 349.5ms（① 的连带）；③ 无先验八分伴奏
  落在 63 而非 126。根因：`beatTracker.ts` 候选排序只看自相关，半速的自相关同样高（拍点是
  真速的子集），慢档常胜。
- 已实验「正拍/反拍能量对比」破平局（权重 0.25 与 0.1 两档）：修好 ①②③ 的同时**打翻等量的
  半速记谱 / @bpm 先验定案用例**（对比度系统性偏向快档，与「半速记谱靠长度比定案」直接冲突）。
  结论：换不来净收益，已回滚，代码保持原状。
- 后续：按「节拍识别 A」路线用真实歌曲建人工参考拍点后再定夺——要放宽 ①②③ 的断言（承认
  纯音频歧义、先验兜底），还是给对比度加更细的证据（重拍模式 / 谱面长度比进排序）。
- 完成标准（不变）：每个失败有明确原因与处理记录，算法调整不能仅为通过断言而牺牲真实伴奏效果。

### 体验、性能与输出【后续排期】

- 整理简谱／五线谱的视觉基线材料，覆盖本轮改变的连线、倚音、波音、拍号、分页和歌词，明确每张图的参数。

- 性能【已测量并优化，2026-10-16】：基准脚本 `npm run perf`（`scripts/perf-test.ts`，覆盖解析／序列化／
  简谱排版／五线谱排版／时刻表／反复展开；绘制与导出需 Canvas，只能在界面测）。
  实测 2000 小节（≈8000 音）：五线谱排版 **10878ms → 179ms（61×）**，500 小节 476ms → 53ms，
  且已由平方级转为线性（4 倍数据 ≈ 3.4 倍耗时），无需按行缓存。三处根因：
  `staff.ts` 每行重算全声部事件（`sourceEvents`／`pitches`／`tiedInto`，行×事件）；
  `pitch.ts` 每颗音用正则重新解析调号（`keyTonic`／`keyOffset` 已加缓存）；
  `staff.ts` 每颗音全表 `.find()` 找拍内组、每根小节线 `indexOf + slice`。
  仍待处理：`expandScore` 在 2000 小节约 200ms 也偏超线性，需要时再查。
- 补齐动态谱生成首次使用的空状态与下一步提示；已有自动识别、打拍和锚点操作不重复开发。
- 打印模板：可配置页眉／页脚和简单封面；现有曲名、调号、速度、作者和页脚并非从零缺失。
- 移动端／平板触控的命中、拖动、歌词输入和工具栏适配，需专项设计与使用验收。
