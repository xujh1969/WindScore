# 听音成谱改造计划

**目标：** 将已选定的人声专用识别、分轨辅助节奏和简谱草稿流程落地，并优化实验界面。

**架构：** React 保留现有谱面内核；GAME 在只监听本机的 Python 服务运行。音频在浏览器解码为 WAV 后发送到本机；鼓/伴奏优先用于节奏估计。原始音符可重复成谱，改变调号和节奏参数不重新推理。

**设计：** 保留品牌金和无衬线字体，面板 10px/控件 6px。DESIGN_VARIANCE 3 / MOTION_INTENSITY 2 / VISUAL_DENSITY 6。左侧音轨与参数，右侧真实谱面预览。展示服务未就绪、空输入、进度、取消、失败和成谱状态。首次只实现歌唱主旋律，不将混合伴奏冒充单旋律。

## 步骤

- [x] 本机 GAME 服务与安装/启动脚本：锁定官方版本、检查权重和依赖，返回原始秒时间音符；验证健康检查、输入限制、实际模型调用。
- [x] 简谱转换：精确保留网格时值、补真实休止、跨小节续音；尊重手选调号与拍号；验证解析、拍数守恒、连音和量化边界。
- [x] 实验 UI：五种分轨、节奏估计、参数重排、谱面预览和试听、明确入库与正确编辑页跳转；验证浏览器布局和错误状态。
- [x] 项目说明更新；类型检查、生产构建、相关回归测试和本机端到端检查。

## 约束与验收

保留已有暂存改动，不提交、不覆盖用户音频和曲库。音频不发送到外部服务。只在用户点击入库时保存草稿。模型未安装时给出可执行的安装/启动说明，不静默退回 Basic Pitch。CPU 性能与真实歌曲准确率必须单独报告；人工或合成样本测试不能宣称真实识别准确率。

模型来源：https://github.com/openvpi/GAME ，权重来源为官方 v1.0.0 release（CC BY-NC-SA 4.0）；第一版固定 medium。本机服务与桌面启动为独立进程，尚不把 Python 模型嵌入 MSI。

## 已验证记录

- 类型检查、生产构建、全部 Node 回归测试通过；Lab 共 67 项检查，包含长音、休止、附点、跨小节延音及解析/序列化往返。
- 本机安装完成：官方 GAME v1.0.3 / medium、PyTorch 2.8 CPU。模型及绕过网络停顿分段下载的依赖均验证完整 SHA256。
- 真实模型对 6 秒合成样本返回 6 个音符，页面生成谱面；此结果只证明推理流程连通，不证明实际歌曲准确率。
- 合成 120 BPM 鼓轨在页面得到对应速度建议；两分轨/四分轨优先级通过逻辑检查。
- 服务健康、Host/Origin/token、无效 WAV/语言、并发限制和真实推理取消检查通过；Windows 取消使用 taskkill /T 结束 venv 启动器及子解释器。
- 浏览器检查桌面/390px 窄屏、浅色/深色布局，修复共享 CSS 顺序导致的高度与网格覆盖。
- 未向用户曲库写入测试曲目，未打包/验证 MSI。真实歌曲识别效果需以用户分离的人声作比较。
- 页面手选 1=G、3/4、90 BPM 后无需再推理即可更新草稿；试听启动与自动结束通过界面检查。导出复用原有 saveTextAsFile；Codex 内嵌浏览器两次未返回 Blob 下载事件，无页面错误，实际落盘尚需普通浏览器/桌面版复核。
