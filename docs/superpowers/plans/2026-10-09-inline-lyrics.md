# 谱面歌词行 Implementation Plan

**Goal:** 按已确认的交互，将歌词作为声部栏中的关联歌词行，在谱面逐音输入。

**Architecture:** 每条歌词行关联一个演奏声部和歌词段号，文字继续存于音符的 lyrics 数组。声部元数据保存歌词行名称；编辑态在既有谱面歌词位置覆盖真实输入框，不另建发声声部或时值数据。

**Tech Stack:** React、TypeScript、Canvas、JPS 3。

## 约束

- 保留旧歌词语法与逐音内容；最多六段。休止符、倚音、小节线不参与输入位置。
- 中文输入法组合期间的空格与方向键不跳音；提交后空格确认并移动一音，空白格允许跳过。
- 可直接点击歌词格或选中音符定位，前奏间奏无需占位输入。
- 修改、命名、删除支持现有撤销；演奏声部移动后关联歌词随行。
- 沿用当前深浅色样式；不新增依赖、不提交其他已有改动、不添加或运行测试套件。

## 步骤

- [x] `types.ts`、`lyrics.ts`、`dsl.ts`：增加歌词行名称及增删改操作；JPS 持久化名称，旧歌词推导默认名称。
- [x] `PartsPanel.tsx`：新增时选择演奏/歌词类型、名称、关联声部；显示歌词标签及选中项配置/删除确认。
- [x] `layout.ts`：为空歌词行预留谱面空间，沿用已存在的歌词绘制与导出。
- [x] `ScoreCanvas.tsx`、新 `LyricCell.tsx`：根据布局覆盖歌词输入格；空格/Tab/方向键移动，中文输入法保护，点击定位、结束输入。
- [x] `EditorApp.tsx`：接入歌词编辑状态与逐音提交，隔离记谱快捷键；旧歌词按钮改为进入歌词行。
- [x] 更新帮助与示例说明；TypeScript 检查、生产构建及人工浏览器查看新增、跳音、跨小节、删除/撤销、名称源码持久化。中文输入法真实桌面选字若无法直接观察，明确标注边界。

## 已观察的页面行为

- 旧版歌词显示为默认行名；通过新增声部选择歌词类型添加第三行。
- 输入「春」后两次空格跳过一音，再输入「风」；跨小节后保存「来」，源码显示正确的逐音占位。
- 自定义名称经源码重新解析保留；删除确认后撤销恢复文字与名称。
- 点击中间音符定位对应输入格；配置关联声部不足以容纳歌词时提示并保留内容；改名后返回输入。
- 含两小节前奏休止、前倚音与中途休止的谱，只为四个主音生成四个歌词格；跳音跨过休止。
- 输入法采用 composition 状态、原生 isComposing 和 229 键码保护。浏览器填入中文不等同于真实桌面输入法选字，本轮未实际验收桌面输入法，也未执行自动化测试或重新验收导出媒体。
- `npm run build` 与 `npm run build:skill` 通过；界面截图保存于 `docs/screenshots/inline-lyrics-light.png`、`inline-lyrics-dark.png`。
