# 安卓局域网上传实施计划

> 按已确认设计在当前会话逐项实现，使用 executing-plans 工作流记录进度；保留已有未提交代码，不推送或合并。

**目标：** 电脑经手机 Wi-Fi 地址每批上传最多九个乐谱包，手机校验入库，双端反馈最终结果。

**架构：** 原生 `LanUploadServer` 管理 HTTP、临时文件、批次和状态；`LanUploadController` 管理 Wi-Fi、前后台与原生桥。WebView 同源获取临时包，经严格校验与持久化后回写原生结果。静态电脑页面轮询状态及发送心跳。

**技术：** Kotlin、NanoHTTPD 2.3.1、Android ConnectivityManager、React/TypeScript、既有包及存储模块。

## 全局约束

- 仅 Wi-Fi 私有地址；允许切换应用发送地址，通知栏服务保持连接；双端亮屏提示，手机回到前台完成入库并自动常亮。
- 每批 1～9 个，仅 `.wspack`；100 MiB/文件、500 MiB/批，失败逐文件说明。
- 同名保留编号；存储成功才反馈成功；不修改既有包格式。
- 不影响播放常亮设置；停用、退出应用和网络变化释放监听与临时资源，转入后台保留监听和暂存队列。

## 模块接口与处理顺序

### 原生服务

- `LanUploadServer.kt` 接收 Wi-Fi 绑定地址、端口、私有缓存目录和电脑页资源；负责心跳、批次、上传、临时文件与结果，不直接操作曲库数据库。
- `POST /api/heartbeat` 更新电脑连接状态；15 秒无心跳视为断开，保留已有导入结果。
- `POST /api/batch` 声明文件名和大小，校验数量 1～9、扩展名、单文件/批次大小和当前是否有未完成批次。校验失败不创建批次。
- `PUT /api/upload/<任务ID>` 流式保存单份二进制包，检查声明大小与实际长度；接收完成进入“待校验”，此时不能报告入库成功。
- `GET /api/status` 返回服务状态、电脑连接状态及逐文件进度/导入结果。接口使用本次启动生成的令牌，不允许跨源访问，不记录或公开令牌。
- 手机原生桥提供启动、停止、状态查询、领取下一份已接收文件、回写任务结果。通过受控同源资源路径读取暂存包，不开放任意文件路径。
- 服务停止时关闭监听和当前传输，未导入任务标记取消，删除暂存包；已有成功结果保留供手机查看。再次启动使用新令牌和新批次。

### 网络与生命周期

- 增加 `ACCESS_NETWORK_STATE`，通过 `ConnectivityManager` 获取 Wi-Fi 网络及其私有 IPv4；不能以互联网连通性作为 Wi-Fi 可用条件。
- 优先使用端口 8080，端口冲突时使用系统分配的可用端口，显示实际可访问地址。
- `LanUploadController.kt` 监听 Wi-Fi 丢失/地址变化，销毁时停止；0.2.78 根据手机反馈加入 `LanUploadService.kt`，通过用户主动启动的 dataSync 通知栏服务支持切去发送地址，保留同一个会话凭证。
- 手机常亮条件为“前台且播放中或上传服务运行中”，停止服务不能误清除正在播放所需的常亮状态。
- 电脑提醒常亮，可尝试浏览器支持的屏幕唤醒能力，但功能不依赖该 API 在 HTTP 地址下可用。

### 校验与入库

1. 逐份校验 ZIP 结构、清单格式/版本、谱面解析、声明音轨是否齐全，拒绝损坏或缺件文件。
2. 保留现有 `readPack` 兼容行为；增加独立严格入口供上传使用，不因新增服务改变 PC 旧包读取规则。
3. 在受控导入模块里保存伴奏、标定和曲库；现有存储有静默失败分支，需要增加可确认失败的保存路径，不能直接把“函数返回”当作保存成功。
4. 同名自动编号，返回实际入库名称；用户停用或转入后台后不启动下一份任务。
5. 成功结果回传原生服务，电脑轮询后展示“手机已导入”；失败返回文件名及可理解的原因，同批继续处理其余文件。

### 页面与浏览器预览

- `AndroidLanUpload.tsx` 挂载于安卓应用层；服务任务处理不能依赖“我的”面板一直展开，切回曲库仍可接收状态。
- “我的”页面保留现有设备文件导入入口，增加服务入口、启停状态、地址复制、亮屏提示和逐文件结果。
- 电脑静态页位于 `public/windscore-upload.html`，独立于 PC 编辑器，支持文件选择/拖放、每批九个、顺序上传、进度、结果与失联提示；双端延续现有清新配色与深浅模式。
- 无原生桥的浏览器预览清楚标注演示模式，不把虚构 IP、模拟心跳或模拟导入当作实际手机服务。真正手机服务必须在 APK 环境验收。

## 验收清单

- [ ] 仅移动网络启动失败，提示连接 Wi-Fi；有 Wi-Fi 但无互联网仍能启动。
- [ ] 电脑首次连入后手机显示“已连接，等待上传”，关闭电脑页面后心跳超时更新为断开。
- [ ] 1 个、9 个文件可处理；10 个、非 `.wspack`、超限体积、损坏包和缺音轨包被正确拒绝。
- [ ] 单份失败不影响同批其他文件，同名保留编号，两端结果名称一致。
- [ ] 存储失败不产生成功提示；成功入库在重启后仍存在，伴奏和标定可恢复。
- [ ] 切去聊天软件发送地址后可从电脑打开原地址；手机在后台接收后，电脑提示返回手机完成校验；手动停用、退出、Wi-Fi 切换时停止接收，已经成功入库的曲目保留。
- [ ] 服务运行时手机亮屏，停止后恢复系统设置；同时播放时不误取消播放常亮。
- [ ] 手机/平板、横竖屏、深浅主题无横向溢出；电脑上传页在浏览器可预览。
- [ ] `npm run build`、`npm run build:android` 和 Android `assembleDebug` 通过；原生网络部分需手机与同局域网电脑联合验收。
