# WindScore 简谱转录与生成

你的任务：把简谱图片（或用户描述的旋律）转录成 `.jps` 内码文件，**并用校验器证明它是对的**。

## 三步工作流

### 第 1 步：读语法

生成任何内容之前，先完整阅读 `reference.md`（与本文件同目录）。它包含：

- 音符记号的完整构造（变音 / 八度 / 附点 / 除法 / 增时线 / 记号后缀）
- 拍内组 `< >`、三连音 `<n: …>`、连音线 `( )` 的规则
- 时值速查表与「每小节拍数必须对上拍号」的硬约束
- 禁用记号清单

### 第 2 步：逐小节转录

1. **先定框架**：从图片中读出曲名、调号（1=?)、拍号、速度、有没有弱起小节、共几小节。读不出的信息（如速度）按风格合理估计并在回复中说明。
2. **逐小节转录，边写边数拍**。这是最重要的一条纪律：
   - `5` = 1 拍，`5-` = 2 拍，`5/2` = 半拍，`5.` = 1.5 拍，`5..` = 1.75 拍
   - 每写完一小节，立刻把该小节所有音的时值加起来，**必须正好等于拍号**（4/4=4 拍、3/4=3 拍）。加起来不对就是你认错了音或认错了时值，回去重看图片，不要继续往下写
   - 一拍内出现两个以上短音 → 用 `< >` 括住，组内合计必须正好 1 拍
   - 三连音写 `<3: …>`（成员合计 1 拍，每音 `/3`）
   - 原谱音符上方的弧线 → `( )`；段落文字（“前奏”“间奏”等）→ `(前奏)`（半角括号包非音符内容）；左右括号记号 → 全角 `（ ）`；结尾小节线必须写 `||`
3. **不许发明语法**。语法表里没有的写法只会报解析错误。

### 第 3 步：校验（不可跳过）

把生成的内容写为 `曲名.jps`，然后在 skill 目录下运行：

```bash
node validate.mjs 曲名.jps
```

校验器独立于任何依赖（node 自带模块之外零依赖），检查五类问题：

| 输出 | 含义 | 处理 |
|---|---|---|
| `[解析错误]` | 记号语法错误 | 对照 reference.md §2 修正 |
| `[I1] [I2] [I4]` | 拍内组时值问题（组合计≠1拍 / 时值粒度非法） | 重算组内时值 |
| `[I3]` | 组内成员不连续 | 检查括号位置 |
| `[I5]` | 连音线分叉 / 并流 | 检查 `( )` 交叉 |
| `小节拍数 ✗ / ⚠` | 小节实际拍数 vs 拍号 | ✗ 必须修；⚠ 检查是否弱起互补 |

**必须循环到输出 `PASS` 才算完成**：修复 → 重跑 → 再修复。不允许跳过校验直接交付，也不允许凭感觉认为"应该没问题"。

PASS 后把 `.jps` 文件交给用户，并附一句简短说明：各小节拍数、组数、是否弱起。用户即可在 WindScore 程序中直接打开该文件。

## 校验器的原理（为什么可信）

`validate.mjs` 内嵌了 WindScore 程序本身使用的解析器与全部不变量（不是重新实现），因此校验通过 ≈ 程序能无损打开：

- 解析错误 = 程序打不开
- I1–I5 = 程序的 BeatGroup / 连线不变量（编辑器里以"谱面校验"呈现）
- 小节拍数徽标 = 程序排版层的同一套校验（含弱起豁免逻辑）
- round-trip = 序列化再回读必须与解析结果完全一致

## 示例

`examples/songbie.jps` 是一首完整的 4/4 谱面（送别，12 小节，含拍内组、三处连音线、弱起无、终止线），可以：

```bash
node validate.mjs examples/songbie.jps   # → PASS
```

转录时对照它的写法：组与连音线如何交叉（`<(3/2 5/2)>`）、长音增时线（`1--`）、高八度（`1^`）、附点（`1^.`）。
